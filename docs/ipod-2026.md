# "iPod 2026" variant

An optional build on top of ring navigation: an Apple Music–style dark UI driven like an iPod,
plus AirPods integration and a fix for a stock Bluetooth audio bug. Everything iPod-specific is
behind build flags; without them `tools/build.py` behaves as before.

This branch is based on `ef76267` and was developed and device-tested on a Q2 up to V2.5R
(September 2026). `main` has moved on a long way since (Coverflow, PEQ, compact, position memory),
so this is offered as a source to cherry-pick from rather than a clean merge.

## Build

```sh
tools/ipod/build.sh "Q2 Firmware V1.32.zip" V2.6R          # release
tools/ipod/build.sh "Q2 Firmware V1.32.zip" V2.6d --dump   # debug logs on the microSD card
```

The script extracts the stock UI assets, generates a theme overlay with `tools/ipod/ipod_theme.py`,
then runs `tools/build.py ... --overlay <overlay> --ipod --row-inset 6 --accel --aac48` and the
test suite. Version strings must be five characters and contain a `V`: `update_firmware`
(0x4f8150) rejects the update otherwise, and the only other check is inequality with the running
version.

| Flag | Effect |
| --- | --- |
| `--overlay DIR` | Replace rootfs files (theme styles, layouts, images) keeping stock metadata |
| `--ipod` | iPod rows, Home, Now Playing and all features below (`RINGNAV_IPOD`) |
| `--row-inset N` | Inset of the rounded selection pill |
| `--accel` | Wheel acceleration (leaf hook on `get_direction`) |
| `--aac48` | Stock bluealsa fix, see below; useful on its own for every build |
| `--dump` | Debug: widget-tree dumps and Bluetooth/AirPods/theme logs to `/mnt/mmc` |

iPod builds compile with `-Oz` and place their scratch cell at 0xb14000 (the patch outgrew 60K);
other builds keep `-Os` and 0xb0f000, so the non-iPod output is unchanged.

## Stock Bluetooth fix (`--aac48`)

When a headset sets up the A2DP stream itself (AirPods taken out of their case connect to the
Q2), it chooses AAC at 44.1 kHz. Shanling's `bluealsa` is then still fed 48 kHz audio: it encodes
44.1 kHz frames and drops about 8% of them (an HCI trace showed ~4 skipped RTP sequence numbers a
second and timestamps running 8% fast). The result is choppy audio until Bluetooth is toggled,
because a connection the Q2 makes itself picks 48 kHz. The fix clears the 44.1 kHz bit in bluealsa's
A2DP AAC source capability (file offset 0x317b7, `c0 01 84 84 e2 00`, verified with the binary's
SHA-256), so headsets pick 48 kHz, which every AAC sink must support. One byte, no code change.

## Features (all in `patch/ringnav.c`, `--ipod`)

- **Lists** (`ipod_rows`, `ipod_row`, `ipod_entry`, `flatten`): flat 30/40/46 px rows with a pill
  selection, two-line song rows, album covers in rows and a three-cover grid (`cover_request`,
  `cover_tick`, `grid_frame`), sort-order radios, fast-scroll letter (`letter_*`).
- **Play All** reachable with the wheel (`head_key`, `head_style`): at the top of a list a detent
  up moves onto the bar, except right after a spin arrives there.
- **Home** (theme layout + `homeart_draw`): an iPod list with a cover pane (panned artwork while
  playing, a wall of cached covers otherwise). **Boots to Home** (`ringnav_boot_play`, a verified
  call-site patch at 0x523de0): the stock resume opened Now Playing; it now resumes the queue paused
  without the page.
- **Now Playing** (`np_extras`, `round_art`, `artbg_sync`): rounded art, a tinted background,
  "3 of 12", time remaining, yoyo scrolling, lyrics that follow the song (`ringnav_scrollto`).
- **Pop-ups** (`dialog_targets`, `dialog_apply`): the wheel and centre button work on confirm
  dialogs; restyled cards, volume HUD, toggles and USB screen come from the theme.
- **AirPods**:
  - Connect card (`btcard_show`): an iPhone-style bottom sheet with battery. Battery and ear
    detection use Apple's accessory protocol (AACP, L2CAP PSM 0x1001, packets as documented by
    LibrePods; `ringnav_aap_thread`, `ringnav_aap_parse`).
  - Ear detection (`ear_tick`): one bud out pauses; all back resumes; nothing plays while no bud
    is in an ear (the stock `player_reconfig` restarts playback on every output switch).
  - Stem buttons (`ringnav_avrcp_thread`, `avrcp_idle`): BlueZ exposes AVRCP pass-through as a
    uinput device "<name> (AVRCP)" that the app never reads (it opens event1-3).
  - Volume: device volume control (`ringnav_btvol`, hook on `mclSetBtVol`); swipes on the AirPods
    are followed (`hs_volume_tick`: the app's level byte at 0xa38c41, then `device_set_volume`),
    with the volume HUD shown when the screen is on.
  - Pauses when the headset disconnects.
- **Theme colour** (Display setting → Theme Colour; `accent_*`): nine dark-mode accents applied
  live from the one theme. Hooks on `style_get_color`, `style_get_gradient` (a leaf; backgrounds
  come as gradients) and `image_manager_add` (decoded images, not `file://` covers) map any colour
  that is pink blended with a neutral onto the accent. Saved in `/mnt/data/ipod_accent`.
- The wheel's Back key is 0xaa (`on_common_keyup`); code-built windows handle it themselves.

## Not included

- The AirPods renders used in the author's personal build (Apple artwork from LibrePods); the
  theme falls back to its own drawn headphones.
- Apple's logo on the boot splash is opt-in (`IPOD_APPLE_LOGO=1`, drawn from the macOS system font
  at build time); by default the stock logo is kept.
- The Home title defaults to "iPod-Q²"; set `IPOD_HOME_TITLE` to change it. "iPod" and "AirPods"
  are Apple trademarks, so rename the variant if you prefer.

## Tests

`tools/test_patch.py` (Unicorn) covers the features above, including the AACP parser and thread,
the AVRCP reader, ear logic, volume sync, theme mapping and the picker page: 214 scenarios in
both debug and release builds.
